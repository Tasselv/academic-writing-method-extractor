# Academic Writing Method Extractor

**把论文读成可操作的写作方法。**

一个用于 Codex 的学术写作分析 skill：从文章全文中提取研究、论证、结构与语言操作，保留出处、变体和使用条件，生成可学习、可复核、可迁移的写作方法手册。

*An evidence-grounded Codex skill for extracting research, argumentation, structure, and language strategies from academic texts. It adapts to the task and genre while keeping observations, interpretations, and recommendations separate.*

## 它能帮你做什么

读完一篇论文，你可能知道它“说了什么”，却仍不清楚它怎样提出问题、组织证据、推进解释。这个 skill 关注这些写作动作：

- 一个宽泛主题怎样被收窄成可回答的问题？
- 概念、材料、数据或形式前提怎样进入论证？
- 章节、段落、表图和公式分别承担什么任务？
- 作者怎样引入他人观点、处理差异、限定自己的判断？
- 哪些操作能迁移到你的题目，哪些只能在特定条件下使用？

可以分析单篇，也可以比较一组文章。单篇得到局部做法；多篇材料才有机会检验反复出现的策略和例外。可以集中研究同一作者，也可以研究某类文章或比较不同写法，无需证明方法为某个人独有。

## 从输入到成品

```text
论文或文章集
    ↓
核对语料、版本与可读范围
    ↓
记录原文动作，重建关键论证
    ↓
比较重复、变体与反向做法
    ↓
形成有出处和条件的方法卡
    ↓
用新材料试做提纲、段落或修改
```

最终可交付：

| 成品 | 包含什么 |
|---|---|
| 写作方法手册 |核心操作、适用问题、执行步骤和边界|
| 证据索引 |文章ID、具体位置、短锚点和对应判断|
| 结构与语言分析 |章节任务、段落推进、句间关系与判断强度|
| 跨篇比较 |重复、变体、反例及文体或时期差异|
| 迁移示范 |根据你的真实材料形成提纲、分析段或修改稿|

成品长度随任务调整，不要求每次都生成整套长报告。

## 安装

### 安装到 Codex

1. 下载本仓库的 ZIP，并解压。
2. 将包含 `SKILL.md` 的整个文件夹命名为 `academic-writing-method-extractor`。
3. 将它放入 Codex 的个人技能目录：

   - Windows：`%USERPROFILE%\.codex\skills\academic-writing-method-extractor\`
   - macOS / Linux：`~/.codex/skills/academic-writing-method-extractor/`

   如果已设置 `CODEX_HOME`，则使用该目录下的 `skills/`。

4. 在后续会话中调用 `$academic-writing-method-extractor`。若当前会话尚未识别，请开启新会话。

安装后应是下面的层级，避免多嵌套一层仓库目录：

```text
skills/
└── academic-writing-method-extractor/
    ├── SKILL.md
    ├── agents/
    │   └── openai.yaml
    └── references/
        ├── corpus-evidence.md
        ├── adaptive-analysis.md
        ├── style-analysis.md
        ├── method-output.md
        └── evaluation.md
```

这是指令与参考文件组成的 skill，无需为技能本身安装 Python 或其他依赖。读取扫描PDF、公式、表格或其他格式时，仍取决于运行环境提供的文档工具。

### 在其他支持技能的工具中使用

可按该工具的技能目录和加载规则放置文件；仓库未逐一验证其他工具的兼容性。也可以直接阅读 `SKILL.md` 及相关参考文件，将其作为人工阅读与写作分析流程。

## 使用示例

将文章放入当前工作区，或提供运行环境能够访问的文件。以下提示可以直接修改使用。

### 1. 从一组文章提取个人方法

```text
请用 $academic-writing-method-extractor 细读我提供的这组文章，
提取该作者提出问题、处理概念、组织证据、安排结构和展开段落的方法。
每个核心方法给出具体出处、执行步骤、跨篇变体和适用边界。
不要求证明这些方法为作者独有。
```

### 2. 只有一篇，先学具体操作

```text
请用 $academic-writing-method-extractor 分析这篇文章。
先做反向提纲，再选出最值得学习的几个论证动作，
说明原文如何完成，并给出可以练习的操作。
只归纳这篇文章，不推断稳定的作者习惯。
```

### 3. 专门分析语言风格

```text
请用 $academic-writing-method-extractor 分析这些文章的语言风格。
比较引言、核心分析和结尾中的句式、段落衔接、引述方式与判断强度。
使用短片段定位，说明形式怎样服务于论证；未经计数不要报告词频或比例。
```

### 4. 用提取的方法处理自己的材料

```text
请用 $academic-writing-method-extractor，根据已提取的方法和我的研究材料，
选择适用的操作，完成研究问题、核心判断和论证提纲。
说明每节需要什么证据，并用现有材料试写一个分析段。
不要用原作者的案例替代我的证据，也不要补造材料。
```

## 一个方法条目应该长什么样

以下为**人为构造的说明性例子**，不来自真实论文，不构成作者特征证据。

> 片段S1：“设整数n为偶数，依定义存在整数k使n=2k。因此n²=2(2k²)，故n²为偶数。”

| 项目 | 提取结果 |
|---|---|
| 可见操作 |将性质展开为定义中的表示，经变换保持目标形式，再返回性质判断|
| 证据定位 |构造片段S1|
| 适用任务 |依赖定义与形式推导的局部证明|
| 执行步骤 |明确假设→写出定义表示→推导目标形式→检查条件→收束|
| 使用边界 |新命题仍需实际证明；不能凭例子或相似句式认定成立|
| 归纳范围 |只观察到这个片段，不能据此认定作者一贯如此|

同样的框架用于实证研究时，应识别变量、研究设计与不确定性；用于规范论证时，应识别价值前提和推演。它不要求所有文章都寻找访谈、实验或因果效应。

## 设计原则

**先观察，再归类。**框架用于整理已发现的动作，也允许出现框架之外的操作。

**让证据能回到原文。**核心判断定位到段落、公式、表图或其他可回查位置，整篇标题不能替代局部依据。

**保留差异。**不同文体、时期、语言与任务可以采用相反顺序，不强行拼成一种统一套路。

**区分四层内容。**原文可见做法、分析者对其作用的解释、迁移建议、针对不足的改良分别标明。

**按任务改变标准。**解释、史料、质性、定量、实验、形式证明、算法工程、综述和规范论证分别使用适合的观察问题；这些入口不是封闭分类。

## 能力边界与验证状态

- 从成稿可以观察论证与表达，不能据此还原作者真实构思、心理活动或全部修改过程。
- 合著、译文、修订版与不完整材料会限制个人归属和风格判断。
- 阅读一篇研究报告不等于复现研究，也不表示已回查其全部来源。
- 结构检查和七个构造场景演练已经完成；这些检查不等于多学科真实全文的效果验证，也没有证明使用该技能必然提高论文质量。

场景、分析输出与限制见[适配演练记录](examples/adaptation-checks.md)。进一步验证与修订的方法见[复核与评估](references/evaluation.md)。

## 如何反馈与改进

欢迎通过 Issue 或 Pull Request 提供具体失败案例。说明输入是什么、技能怎样误读、原文哪些位置与其判断不符，以及建议如何调整；如分享文章片段，请只提供你有权公开的必要内容。

优先修正可复现的错误，例如错误归属、过度概括、风格判断缺证据或不适当的文体要求。增加学科名称或方法条目本身不视为通用性提升。
